AgentOS v2.20 test notes

This build adds a contextual category browser alongside the PDF and removes the duplicate raw-text display for agents. Frequent questions tiles, clear Knowledge setup, safer file replacement and return-to-results navigation remain available. Bulk demo acceptance, OPS placement review, draft recovery and visual comparison remain available. These notes support your review period; the full Admin Guide will follow after the demo build is agreed.

Open AgentOS v2.20 · Open the standalone importer

Test the v2.20 category browser

  1. Save unfinished Admin work as a review draft, keep your prior app and JSON as backups, and open the new index.html. Confirm v2.20. Load your existing exported pack and matching PDF through Knowledge. No reimport is needed.
  2. Open a procedure. On a wide screen, More in [category] appears to its right while your existing left navigation remains. On smaller screens, select Show subjects above the procedure; the browser opens above the PDF so it does not squeeze its reading width.
  3. Try one of the six common direct links. Expand a subcategory to reach the other procedures. Labels omit redundant category prefixes; the original full heading remains above the PDF. Unavailable and pending source records are not offered as right-panel shortcuts.
  4. Type in Search [category]. Only the right panel filters; the PDF remains in place. Clear restores the common links and subcategories. Enter opens a unique match; with multiple matches, choose a visible result.
  5. Open another article from that panel. The category filter, expanded subcategories and panel scroll position should remain. Use Back to restore the previous PDF page, zoom and reading position.
  6. Expand a different major left category without selecting an article. The right panel should continue to reflect the procedure being read. Selecting an article in another category changes the right panel to that category.
  7. Try Hide subjects, Show subjects, and the PDF's Expand / Exit expanded view. The panel is hidden in expanded PDF view. Check at your normal work-screen size and browser zoom.
  8. The raw extracted-text section no longer appears in the agent procedure view. Text is still available for searching and Admin review/comparison. Any separately authored reviewed answer remains available in a collapsed section. Reviewed “If the customer also…” relationships remain separate from general category browsing.

Adjust right-panel subcategories

In Admin, edit the existing pack or resume your draft, select a subject, and use Right-panel subcategory in the mapping controls. Leave blank for the automatic heading-based suggestion, select a suggested label, or type an OPS-approved label. This changes only the right-panel grouping; it does not change the foundational category, source review status, or article relationships. The existing common-need preference prioritizes direct links. Save your draft and export/apply the appropriate updated pack to refresh AgentOS.

Navigation, draft/pack roundtrips, file retention and reading-position behavior were checked with simulated interface events; PDF extraction and rendering were also checked with sample files. Please verify the actual layout in your work browser.

Review categories with OPS

  1. Open Needs placement in AgentOS. It shows a searchable list of accepted subjects waiting for category decisions.
  2. Select Review placement with OPS. The existing demo admin gate still applies. If the current Admin workspace matches the displayed demo, it opens that workspace and keeps its pending review details. If another unsaved workspace would be replaced, the app asks first.
  3. In OPS placement review, select individual subjects or Select all matching. Use the Show filter and search to narrow the list. Changing either filter clears the selection so hidden subjects are not assigned accidentally.
  4. Choose an existing navigation group and select Assign group. This marks the placement as an OPS/manual choice without changing the subject's source-review status.
  5. You can also select Apply clear suggestions to unassigned subjects. This preserves manual choices and subjects flagged for new-group discussion.
  6. To propose a new group, enter a name under Propose a new group for OPS discussion, then flag the selected subjects. They stay in Needs placement. The proposal is saved with the subject; no new navigation group is created automatically.
  7. Select Done, export the updated demo pack and use it in AgentOS. Attach the matching PDF again and confirm the subjects moved to the intended group. Save the review draft to continue later.

Use All mapped subjects in the OPS dialog to correct placements outside Needs placement. The familiar foundational groups and icons remain in place.

Which subjects are excluded

Bulk acceptance excludes missing, ambiguous, unreadable or empty matches; changed text; possible visual changes; unavailable visual comparisons; manual ranges needing review; unusually long excerpts; uncertain end boundaries; possible section headings; and unfinished authored answers or formatting. Existing reviewed or unavailable decisions are preserved. An uncertain category alone does not block demo acceptance when the source match is otherwise eligible.

Relationships still require individual review of both source and destination before the relationship can be approved. Bulk demo acceptance does not approve article relationships or policy wording.

What to watch during your review

  • Keep your familiar main groups, icons, six common needs, search, original-PDF reader and reviewed related-article links in the demo.
  • Review drafts and knowledge packs contain manual text. Local file selection and these new comparison features add no network service. Original PDF bytes are not embedded in a saved draft or knowledge JSON.
  • Large manuals now include a page-image pass, which adds processing time. The importer still requires selectable text and does not provide OCR. File limits remain 150 MB for PDFs and 30 MB for agent knowledge packs; review drafts have a 150 MB limit.
  • A synthetic 800-page manual with 573 selected mappings completed text extraction, page-image hashing and draft validation in testing. Those were simple generated pages; your real manual and work VM still need their own timing and usability check.
  • Automated checks used actual PDF rendering with simulated interface events. Your work-browser testing remains the check for layout, interactions and local environment behavior.

For feedback, record the procedure ID, action taken, expected result and actual result. Keep the relevant draft and exact PDF so the workflow can be repeated locally.
