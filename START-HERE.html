v2.25 — six pilot refinements

Use the same index.html path and browser profile to retain existing saved knowledge and favorites. This update does not require reimporting or comparing the manual.

  1. Single-article lists: a returned list containing only one original article has no filter. A multi-article list keeps its filter when narrowed to one. Direct single-result searches no longer add an unnecessary Return to results button.
  2. Active article previews: the article open in the main viewer is excluded from popups everywhere. Opening an article closes its matching popup, even when pinned. Other article previews still work.
  3. Favorites help: the information icon is now an 18 px outline inside a 32 px target. Click it or activate it with Enter/Space to show storage help; Escape closes help.
  4. Preview settings: beside PDF previews, select Preview settings. Independently enable left navigation, right panel, or Quick answers/search/other article links. Close settings when done. Preferences save immediately in this browser. The master toggle turns all previews off/on without losing your selections.
  5. Readable reporting: Admin → Pilot usage report now shows H:MM:SS, focused article time, average per active day, article opens and daily rows. Expand the details for visible time, individual articles and Admin/setup activity. Admin-only days are excluded from the average denominator.
  6. Lookup journeys: select New lookup to explicitly start a fresh attempt. Otherwise the first navigation/search action starts one automatically; URL handoffs start their own journey. Navigate to an article and optionally select Found what I needed to confirm success. The next navigation after confirmation starts another journey. Use New lookup to separate unrelated needs during the same call.

  • Launch the supplied escrow_help URL with the matching sample knowledge pack. Its primary article should have zero navigation clicks. Confirm it and check the separate automatic-handoff results.
  • Try a lookup with several article choices and searches. Start New lookup without confirming; the earlier journey should be unconfirmed.
  • Open Admin → Pilot usage report. Review the daily average, manual/automatic click buckets and expandable lookup details. Export usage CSV and lookup CSV separately.

Timing is browser-focused time, not confirmed reading. First-article time ends when the article is selected; confirmed time includes the time spent reviewing it before confirmation. PDF loading time is not separately measured. Preview selections count as navigation actions; zoom, PDF paging, Favorites editing and Admin actions do not. Keyboard button activation is counted like a click. Searches are settled typing bursts (700 ms pause or navigation); later bursts are refinements, not a claim about intent changes.

Lookup records contain article IDs, release, counts and timings—not customer words, loan information or search text. A lookup is not a call. Closed/interrupted unfinished journeys are unconfirmed; without confirmation we do not assume the last article answered the question. Pausing tracking ends any active lookup as unconfirmed. Retention is bounded to 30 days / 100 tab sessions, with up to 500 completed journeys per tab session. Use one tab per pilot agent and export each browser separately. Clear local usage removes both usage and lookup histories while keeping your manual and favorites.

New in v2.22: set up each agent once

  1. Extract the ZIP to a stable approved folder. Keep index.html at the same path for subsequent calls. Use the same normal browser profile; private browsing is not suitable for retention.
  2. Open index.html. In Knowledge, select the exported JSON and exact matching PDF.
  3. Scroll to Remember on this device and select Remember current release on this device. Wait for the saved confirmation. This stores a local browser copy of the pair; it does not publish anything.
  4. Close the tab, then reopen the same file. Confirm the saved release restores and an article's PDF opens without selecting files again.
  5. Launch that same address with a configured intent parameter, for example ?intent=escrow_help when using sample-intent-knowledge.json. FlightDeck restores the saved pair before routing. Try several calls.
  6. Repeat setup separately for each agent/browser profile. If company policy blocks storage or the browser clears its data, load the files again. Persistence is not guaranteed by this demo.

To update the manual, choose Replace saved manual, load the replacement JSON and matching PDF, then remember the new pair. The prior saved pair remains until the replacement is validated and committed. Exports and Admin changes do not automatically update every agent.

Forget this device’s copy removes its saved pair and favorites. The already-loaded session and original files remain available. Reset loaded knowledge only clears the session; use Forget to remove the saved browser copy. Other open tabs may still hold their own loaded copy; close them if needed. Expanded preview controls

Previews now open at approximately 800px wide (smaller on narrow screens), use up to 85% of browser height, and open toward the content area. The PDF scrolls within the popup. Single-page articles omit Previous/Next.

Choose Fit width, 125%, or 150% to enlarge the actual PDF. Pin preview keeps it open when the pointer leaves; Unpin restores hover behavior. Close preview, Escape, opening the article, or entering Knowledge/Admin closes it. A new pack also closes it. Configure intents without editing code

  1. Open Admin using the existing demo entry. In the outer Admin bar, select Edit current pack intent routes to bring your loaded pack into the editor. If you have unsaved Admin work, save it first. Alternatively, choose a pack as the previous file in Admin, then Edit loaded knowledge pack — no PDF needed.
  2. Select Manage intent routes. Existing routes and missing/unavailable destination warnings are listed. Search for a route or choose Add intent route.
  3. Enter a name, incoming parameter and matching values, one per line. Parameters are intent, OBCampaignName and IBUtterance. Exact matching normalizes capitalization, punctuation, hyphens/underscores and whitespace.
  4. For IBUtterance only, you may choose Contains whole phrase. This is literal matching, not language understanding: “do not make a payment” can still contain “make a payment.” Prefer specific exact aliases or structured intent codes when available.
  5. Search the article catalog and click + to link several articles. Link all matching articles adds the filtered set. Earlier / Later sets their order; Unlink removes only that route connection.
  6. Choose Show article choices or Open primary article. For primary mode, select Set primary on the desired article. Keep other relevant articles linked as one-click choices.
  7. Select Save route. Route changes are saved in the current Admin workspace, not automatically published. Use the tester below to enter one or several incoming values. It tests saved routes; an unfinished editor is excluded.
  8. Use Export demo knowledge pack / Use demo pack in AgentOS if the release contains demo acceptance or pending review; use the reviewed-pack actions for a fully reviewed release. Save review draft retains unfinished overall review work. Save the open route editor before exporting or saving a draft.
  9. Reload the exported pack in Knowledge and attach its exact PDF. Reopen Admin to confirm the routes, article order and primary selection persisted.
