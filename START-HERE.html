FlightDeck v2.28

Standalone pilot update based on v2.26. This is separate from the centralized v2.27 deployment package.

Start testing

  1. Keep a backup of your existing index.html and exported knowledge pack. Save unfinished Admin work as a review draft.
  2. Replace your standalone index.html with the supplied index.html. Use the same filename, location and browser profile when possible. Do not clear browser storage.
  3. Open index.html normally. If your saved knowledge does not restore, use Knowledge to select the exported knowledge pack and matching Flight Manual again. Existing pack and draft formats are retained.
  4. Use your existing pilot Admin entry. This update does not change those credentials or turn the local demo gate into production authentication.

Agent feedback

The reader toolbar now has Helpful? 👍 👎 beside Source details. A rating saves immediately. Thumbs-down opens optional reason choices and a 500-character comment. Choose Save details to keep the comment, or Done / skip details to close without saving typed comments. Do not enter customer, account or loan information.

Each article and release has one editable rating in this browser. Changing to thumbs-up clears the negative reason/comment. Different releases keep separate records. Admin → View article feedback displays the records; Export article feedback downloads CSV with article ID, title, release, document fingerprint, rating, reason, comment and update time. These controls are in the embedded Admin workspace in index.html. A separately opened knowledge-admin.html does not read another page’s feedback.

No feedback is sent to a server. Browser storage clearing or changing browser profiles can remove or isolate records. Export feedback separately from each pilot browser. There is no automatic team-wide ranking or collection.

Review Subjects

  • Source and placement statuses are separate. Main navigation group stays visible; optional label editing, Navigation details, Quick access settings, search phrases and authored guidance are collapsed.
  • Approve & next still requires verification of the correct procedure and complete pages, including tables. It advances through unresolved subjects in your current filter/search.
  • Skip for now leaves the subject pending. When no other unresolved subjects match the current queue, the screen stays put and explains that you can change filters.
  • Source issues and Changed procedures filters complement the existing filters. Visual changes are included in Changed procedures.
  • Mark unavailable retains a withheld procedure record. Remove from this release is under More actions.
  • Successful matches keep correction tools collapsed; questionable matches open them. Changed procedures show extracted-text comparison prominently.
  • Existing bulk demo acceptance and Needs placement workflows remain. Demo acceptance is not manual source approval.

Compare previous and updated PDFs

  1. Select the previous PDF or knowledge pack, then the updated PDF, and run Read / compare PDFs.
  2. In Review Subjects, View previous PDF and View updated PDF use each version’s own physical start page.
  3. If only a previous JSON pack was supplied, use Attach matching previous PDF in the review panel. Its fingerprint must match that pack. Reattach after reopening a saved draft.
  4. A first import shows View current PDF only. Missing sections are identified instead of linking an unrelated section.

The agent’s Open full manual link is removed. Knowledge browsing opens mapped procedures in the workspace. Manual-access links remain available for Admin source inspection. This is a workflow change, not a security boundary against access to a local PDF.

Suggested acceptance checks

  1. Load your existing pack and matching PDF; verify favorites, intents, previews and procedure navigation.
  2. Rate an article negatively, select a reason, enter a test comment and save. Check Admin view and CSV. Change the rating and verify the update.
  3. Review two sample PDFs. Verify that both source buttons open at the correct pages.
  4. Filter to Needs review and search a term. Approve a subject, then skip another. Confirm the queue/search remain intact and skipped subjects remain pending.
  5. Save and resume a review draft. Verify navigation preferences, authored guidance and source states are preserved.
